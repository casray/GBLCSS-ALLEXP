Graph-aware Granular Ball 最小验证报告

日期：2026-06-01。用途：给 GPT / Deep Research 继续设计下一阶段研究。实验目录：C:\Users\Admin\Desktop\实验8去噪5.19-\gb_graph_aware_minival_6_1

一句话结论：当前 v1 有局部纯度信号，但还不是成功方法。gagb/gagb_ca_ce 相对普通 gb 在 3/4 个 dataset-noise 设置上有小幅 accuracy 正向；但没有稳定打过 khop_only 和 gagb_shuffled，并且 noise_detection_auroc 没有稳定优于普通 GB。

1. 研究问题

本次最小验证的目标不是提出完整论文方法，而是检查一个更小的假设：

在 frozen GRACE embedding 上构造粒球时，
普通 embedding-only GB 是否因为忽略图拓扑而不够好？
如果加入 k-hop topology 约束，
Graph-aware GB 是否更适合作为 noisy-label node classification 的局部软监督单元？

粒球在本实验中的角色被严格限制为：

  • 局部 soft-label 统计单元。
  • 样本 reliability / weight 区域。
  • 机制诊断对象，例如 clean purity、noisy-label entropy、noise detection AUROC。

粒球没有被用作 hard positive label、hard negative filter、prototype pulling 目标，也没有修改 GRACE view generation。

2. 算法流程

2.1 输入和基本设置

项目内容
输入图Attributed graph G=(V,E,X)，节点标签含 symmetric noise。
embedding复用 frozen GRACE encoder 产生的归一化节点表示 H。
拓扑信息从 embedding payload 中保存和读取 edge_index。
标签使用限制构球阶段不使用 noisy label 或 clean label。clean label 只用于诊断指标。
核心参数max_hops=2, min_ball_size=5, tau_add=0.55, lambda_h=0.7, lambda_t=0.3, max_ball_size=128。

2.2 Graph-aware GB 构球步骤

  1. 对输入 embedding 做 L2 normalization，得到单位向量表示。
  2. 由 edge_index 构造无向邻接表，并计算每个节点 degree。
  3. 维护未分配节点集合 U。
  4. 每一轮从 U 中选择中心节点：degree 最大者优先，随机数只用于微小 tie-break。
  5. 从中心节点出发，在未分配节点中做 BFS，收集 max_hops 内候选节点。
  6. 对每个候选节点计算 embedding 相似度和拓扑相似度。
  7. 用混合分数筛选成员：score(i,c)=lambda_h*cos(h_i,h_c)+lambda_t*topo(i,c)。
  8. 其中 topo(i,c)=1 如果是中心本身，否则 1/hop_distance(i,c)。
  9. 保留中心节点和所有 score >= tau_add 的候选节点。
  10. 若球大小小于 min_ball_size，按 score 从高到低补足；若超过 max_ball_size，截断。
  11. 将选中节点从 U 中删除，继续下一轮直到所有节点被分组。
  12. 对每个球计算中心、半径、节点到中心距离和 ball diagnostics。

2.3 伪代码

Input: normalized embeddings H, edge_index
U = all nodes
Adj = undirected_adjacency(edge_index)

while U is not empty:
    c = argmax_{v in U} degree(v)
    C = k_hop_candidates(c, Adj, U, max_hops=2)
    for i in C:
        emb_sim = cosine(H[i], H[c])
        topo_sim = 1.0 if i == c else 1.0 / hop_distance(i, c)
        score[i] = 0.7 * emb_sim + 0.3 * topo_sim
    B = {c} union {i in C: score[i] >= 0.55}
    if |B| < 5:
        add highest-score candidates until |B| = 5
    B = first 128 nodes by score
    assign B as one graph-aware ball
    U = U - B

Output: group_ids, groups, centers, radii, node_distances, diagnostics

2.4 方法变体

方法定义目的
ce普通 noisy-label CE。基础下界。
global全局 label distribution smoothing。排除“只是 smoothing 有效”。
kmeans用 KMeans 替代 GB，组数匹配 GB。普通聚类对照。
topk_matched按 embedding top-k 邻居做局部 smoothing。局部邻居对照。
gb普通 embedding-space granular ball。核心 baseline。
gb_ca_ce普通 GB + coverage-aware CE fallback。避免未覆盖节点被错误处理。
gb_weighted_ce普通 GB reliability weighted CE。权重型粒球对照。
gagbGraph-aware GB strict local smoothing。核心候选方法。
gagb_ca_ceGraph-aware GB + coverage-aware CE fallback。核心候选方法，覆盖更稳。
gagb_weighted_ceGraph-aware GB reliability weighted CE。检验球作为权重区域是否有效。
khop_onlylambda_h=0, lambda_t=1 的 topology-only grouping。判断收益是否只是拓扑邻近。
gagb_shuffled保留 GAGB 球大小分布，但随机打乱成员。排除“只是分组大小/正则化”有效。

5. 判定

预设成功标准是否满足证据
gagb 或 gagb_weighted_ce 在至少 3/4 个设置中 paired mean 超过普通 gb部分满足gagb 对 gb 在 CiteSeer 0.2、CiteSeer 0.4、Cora 0.2 为正，但 Cora 0.4 为负。gagb_weighted_ce 整体不强。
gagb 打过 khop_only 和 gagb_shuffled不满足CiteSeer 0.2/0.4 上输给 khop_only，CiteSeer 0.2 上也输给 gagb_shuffled。
noise_detection_auroc 至少 3/4 设置优于普通 GB不满足gagb 的 AUROC 四个设置都低于普通 gb。gagb_ca_ce 只在 Cora 0.2 和 Cora 0.4 超过 gb。
clean_damage_rate 不高于 ordinary GB 超过 1 个百分点满足当前诊断中 clean damage rate 为 0.0。

6. 解释：哪些信号是真的，哪些不能过度解读

6.1 已被实验支持

  • Graph-aware / topology-aware 分组能显著降低 noisy-label entropy。例如 CiteSeer 0.2 中，gb 为 0.2047，gagb 为 0.0864，khop_only 为 0.0692。
  • gagb 在 clean purity 上通常高于 ordinary gb；但 khop_only 往往更高。
  • gagb_ca_ce 比 strict gagb 更稳一些，尤其在 Cora 0.2。

6.2 尚未被支持

  • 不能说 graph-aware GB 已经优于 topology-only grouping。
  • 不能说 graph-aware GB 已经带来稳定噪声检测能力，因为 AUROC 没有稳定超过 gb。
  • 不能把当前 accuracy 小幅提升写成显著提升；多数提升接近或小于 std。
  • 不能声称这是 paper-ready 主方法。

6.3 可能的机制解释

  • 拓扑约束确实让球更纯，但更纯的球未必能更好纠正 noisy labels。
  • 当前 soft-label 构造可能过于保守，导致 noise_correction_rate=0.0。
  • khop_only 的强表现说明，在 Cora/CiteSeer 这类同配图上，拓扑邻近本身已经非常强；混合 embedding score 未必增加有效信息。
  • gagb_shuffled 在部分设置上很强，提示当前收益可能混有分组大小、coverage 或训练随机性的影响，必须继续做控制实验。

7. 给 Deep Research / GPT 的下一步问题

建议把下面这段作为后续研究提示词的一部分：

我已经完成 Graph-aware Granular Ball v1 的最小验证。
任务是 noisy-label robust node classification on attributed graphs。
当前方法在 frozen GRACE embedding 上构球：
score(i,c)=0.7*cos(h_i,h_c)+0.3*(1/hop_distance(i,c))，
候选节点限制在 2-hop 内，不使用 noisy label 或 clean label 构球。

实验结果：
1. gagb/gagb_ca_ce 相对 ordinary gb 在 3/4 个 dataset-noise 设置上有小幅 accuracy 正向。
2. 但 gagb 没有稳定打过 khop_only 和 gagb_shuffled。
3. gagb 的 clean purity 更高、noisy-label entropy 更低，但 noise_detection_auroc 没有稳定超过 ordinary gb。
4. noise_correction_rate 当前为 0，说明 soft-label target 可能太保守。

请基于这些结果继续研究：
- 这个方向是否应该继续？
- 下一版应该优先改构球、soft-label target、reliability weight，还是改 evaluation diagnostics？
- 如何区分 topology-only benefit 和 graph-aware GB-specific benefit？
- 是否需要把 topology 权重做成 homophily-aware / confidence-aware？
- 怎样设计一个更能产生 noise correction 的 q_B，而不是只降低 entropy？
- 哪些实验控制必须加入，才能避免把 khop/topology smoothing 误写成粒球贡献？
要求输出：研究判断、v2算法设计、消融实验、失败标准和论文 claim 边界。
