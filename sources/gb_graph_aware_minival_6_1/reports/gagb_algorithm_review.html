Graph-aware Granular Ball (GAGB) Fair-Comparison Review Pack

面向 GPT / 同行审查的算法说明、流程复现、关键代码摘录与当前最小验证结论。

审查目标： 判断当前 Graph-aware GB v1 是否在 frozen-GRACE noisy-label gate 中证明了独立价值。 这里的“独立价值”不是只超过 ordinary GB，而是要超过 embedding-only greedy、topology-only、GAGB-matched kmeans/top-k 和 alpha-matched shuffled grouping 等公平控制组。

1. 当前研究问题

任务族是 带噪标签属性图节点分类。输入为属性图 G=(V,E,X)、 部分训练节点的 noisy labels，以及 frozen GRACE 预训练得到的节点表示。目标是在不改变 backbone 训练协议的前提下，验证图感知粒球是否能作为局部可信区域，帮助 noisy-label smoothing 或 reweighting。

本轮只做最小验证，不声称完整方法已经成立。当前实验不接入 RTGNN，不加入 prediction consistency， 不加入 Q(B) 质量函数，不调 alpha，不扩展 PubMed 或 pair noise。

2. 核心假设

ordinary embedding GB 只看表示空间相似性，可能把图上距离很远但 embedding 接近的节点放进同一个球。 GAGB v1 试图让球同时满足两个条件：

  1. embedding 上接近，说明语义或表示相似。
  2. 图拓扑上局部可达，说明局部结构关系更可信。

如果这个假设成立，GAGB 生成的球应当比 ordinary GB、纯拓扑分组、随机同尺寸分组和普通聚类更适合作为 noisy-label smoothing 的局部监督单元。

4. GAGB 构球算法

核心函数位于 src/noisy_label_gb_grace/balls/graph_aware_ball.py::build_graph_aware_balls。 输入为 normalized embedding H、edge_index 和构球参数。

4.1 输入参数

参数 含义 当前默认 / 用法
embeddings 节点表示矩阵 H 通常是 L2 normalized GRACE embedding
edge_index 图边 构造无向邻接表，用于 k-hop candidate 和 topo score
max_hops 局部候选范围 默认 2
min_ball_size 最小球大小 不足时补最高分候选
max_ball_size 最大球大小 默认 128，避免巨型球
tau_add 成员加入阈值 score 大于阈值加入
lambda_h embedding 相似性权重 GAGB 使用 0.7
lambda_t topology 相似性权重 GAGB 使用 0.3
candidate_scope 候选池范围 khop 或 global

4.2 成员分数

对中心节点 c 和候选节点 i，GAGB v1 使用线性组合分数： 

score(i, c) = lambda_h * cosine(z_i, z_c) + lambda_t * topo(i, c)

topo(i, c) = 1.0                 if i == c
           = 1.0 / hop_distance  if i reachable within max_hops
           = 0.0                 otherwise

4.3 Greedy 构球伪代码

unassigned = all nodes
while unassigned is not empty:
    center = unassigned node with largest degree plus tiny random tie break

    if candidate_scope == "khop":
        candidates = unassigned nodes within max_hops from center
    else:
        candidates = all unassigned nodes

    score each candidate with lambda_h * cosine + lambda_t * khop_similarity
    members = candidates with score >= tau_add

    if len(members) < min_ball_size:
        members = top-scoring candidates up to min_ball_size

    members = top-scoring members up to max_ball_size
    assign all members to the current ball

return group_ids, groups, centers, radii, node_distances, diagnostics

4.4 关键代码摘录

def build_graph_aware_balls(
    embeddings: torch.Tensor,
    edge_index: torch.Tensor,
    *,
    max_hops: int = 2,
    min_ball_size: int = 5,
    max_ball_size: int = 128,
    tau_add: float = 0.55,
    lambda_h: float = 0.7,
    lambda_t: float = 0.3,
    lambda_p: float = 0.0,
    teacher_probs: torch.Tensor | None = None,
    candidate_scope: str = "khop",
    seed: int = 0,
) -> GraphAwareBallResult:
    if candidate_scope not in {"khop", "global"}:
        raise ValueError("candidate_scope must be 'khop' or 'global'")

    z = F.normalize(embeddings.detach().cpu().float(), p=2, dim=1)
    adjacency = _build_adjacency(edge_index, z.size(0))
    degrees = torch.tensor([len(neighbors) for neighbors in adjacency], dtype=torch.float32)

    unassigned = set(range(z.size(0)))
    groups: list[list[int]] = []
    centers: list[int] = []

    while unassigned:
        center = _select_center(unassigned, degrees, rng)
        hop_dist = _khop_distances(center, adjacency, max_hops)

        if candidate_scope == "khop":
            candidates = [node for node in hop_dist.keys() if node in unassigned]
            if center not in candidates:
                candidates.append(center)
        else:
            candidates = list(unassigned)

        scored = []
        for node in candidates:
            cos = float(torch.dot(z[center], z[node]).item())
            topo = _topology_similarity(node, hop_dist)
            pred = _prediction_similarity(center, node, probs)
            score = lambda_h * cos + lambda_t * topo + lambda_p * pred
            scored.append((score, node))

        scored.sort(key=lambda item: (-item[0], item[1]))
        members = [node for score, node in scored if score >= tau_add]
        if len(members) < min_ball_size:
            members = [node for _, node in scored[:min(min_ball_size, len(scored))]]
        if len(members) > max_ball_size:
            members = members[:max_ball_size]

        for node in members:
            unassigned.remove(node)
        groups.append(members)
        centers.append(center)

5. Fair-Comparison 控制组设计

本轮 patch 的核心不是让 GAGB 涨点，而是让结论可审查：GAGB 是否真的优于若干只缺少一个因素的对照组。

方法 设计目的 与 GAGB 的差异
gb ordinary embedding GB 不用图拓扑，不用 GAGB greedy builder
gagb 当前主方法 candidate_scope=khop, lambda_h=0.7, lambda_t=0.3
emb_only_gagb_local 隔离 topology score 的价值 同样 k-hop candidate，但 lambda_h=1.0, lambda_t=0.0
emb_only_gagb_global 隔离 k-hop candidate restriction 的价值 global candidate，embedding-only score
khop_only 判断是否只是 topology grouping 有用 lambda_h=0.0, lambda_t=1.0
kmeans_gagb_matched 控制 group count KMeans 的 K 等于 GAGB ball count
topk_gagb_matched 控制 smoothing neighborhood size k 等于 GAGB eligible train nodes 均值减一
gagb_shuffled_size_only 旧 shuffled 控制 保留球大小分布但打乱成员；alpha 和 coverage 可能变化
gagb_shuffled_alpha_matched 更干净的随机控制 保留球大小分布，并复用 GAGB per-node alpha 与 coverage

6. Smoothing Target 构造

目标构造位于 src/noisy_label_gb_grace/smoothing/targets.py::build_method_targets。 clean label 只用于 diagnostics，不进入训练 target。

6.1 局部 soft label

对一个 group / ball，只使用训练节点 noisy labels 统计标签分布： 

q_B[y] = count(noisy_label == y among train nodes in B) / train_node_count(B)

target_i = (1 - alpha_i) * one_hot(noisy_y_i) + alpha_i * q_B

alpha_i 由局部半径和节点到中心距离得到。覆盖不到或不满足条件的节点回退到 noisy one-hot target。

6.2 Alpha-matched shuffled 控制

gagb_shuffled_alpha_matched 的关键是：成员随机打乱后，训练时复用原始 GAGB 的 alpha_i 与 coverage mask，只改变每个节点拿到的 shuffled group label distribution。 这样可以避免 shuffled 控制组因为干预强度变化而不公平。 

def _local_group_targets(
    labels_noisy: torch.Tensor,
    train_mask: torch.Tensor,
    groups: list[list[int]],
    *,
    num_classes: int,
    alpha: float,
    group_ids: torch.Tensor,
    node_distances: torch.Tensor | None = None,
    radii: torch.Tensor | None = None,
    alpha_override: torch.Tensor | None = None,
    coverage_override: torch.Tensor | None = None,
) -> tuple[torch.Tensor, torch.Tensor, dict[str, float]]:
    targets = F.one_hot(labels_noisy, num_classes=num_classes).float()
    weights = torch.ones(labels_noisy.numel(), dtype=torch.float32)
    alpha_values = torch.zeros(labels_noisy.numel(), dtype=torch.float32)
    covered = torch.zeros(labels_noisy.numel(), dtype=torch.bool)

    for group_index, nodes in enumerate(groups):
        train_nodes = [node for node in nodes if bool(train_mask[node])]
        if not train_nodes:
            continue

        label_dist = _label_distribution(labels_noisy[train_nodes], num_classes)
        for node in train_nodes:
            local_alpha = _node_alpha(node, group_index, alpha, node_distances, radii)
            if alpha_override is not None:
                local_alpha = float(alpha_override[node].item())
            targets[node] = (1.0 - local_alpha) * targets[node] + local_alpha * label_dist
            alpha_values[node] = local_alpha
            covered[node] = True

    if coverage_override is not None:
        covered = coverage_override.bool().clone()

    return targets, weights, diagnostics

9. 当前最小验证结果

当前结论： GAGB v1 没有通过独立价值标准。它在 3/4 个 dataset-noise setting 上略高于 ordinary GB， 但没有稳定超过 khop_only、emb_only_gagb_local/global、 kmeans_gagb_matched、topk_gagb_matched 或 gagb_shuffled_alpha_matched。

gagb_shuffled_alpha_matched 的 sanity diagnostics 在四个 setting 中均为： alpha_match_max_abs_diff = 0.0， coverage_match_abs_diff = 0.0。 因此该控制组在干预强度上是干净的。

10. 需要 GPT 重点审查的问题

  1. GAGB 是否真的只比控制组多了 graph-aware score？ 特别是 emb_only_gagb_local 与 khop_only 是否足以拆分 embedding score 和 topology score。
  2. gagb_shuffled_alpha_matched 是否足够干净？ 它保留 alpha 与 coverage 后，只改变 shuffled group label distribution，这是否是合适的随机控制？
  3. topk_gagb_matched 的匹配规则是否合理？ 当前使用 mean eligible GAGB train nodes minus 1，而不是 all-node avg ball size。
  4. target construction 是否存在 noisy-label self-confirmation？ 当前局部分布完全由同一批 noisy train labels 统计，可能强化局部错误多数类。
  5. 当前失败说明什么？ 是图感知粒球思想不成立，还是 v1 的构球质量函数太弱、alpha 机制太粗、缺少 prediction consistency？
  6. 是否值得进入 v2？ 如果值得，v2 应优先加入 prediction consistency、ball quality Q(B)、 homophily-aware weighting，还是完全换成可学习增强 / view optimization？

11. 当前可接受的论文表述边界

当前不能写成“GAGB 已证明优于普通 GB 或其他控制组”。更合适的表述是：

在 frozen-GRACE noisy-label gate 中，GAGB v1 展示了构造图感知局部分组的可执行性， 但公平控制组显示其独立贡献尚未被稳定证明。当前版本更适合作为诊断基线，而不是主方法。
