GAGB v2 Target-Only Minival Review Pack

给 GPT / 同行审查用：包含下一步 v2 的计划、算法、代码接口、实验结果和当前结论。

一句话结论： Target-only v2 没有通过成功标准。它证明了 teacher-aware target pipeline 可以运行，而且 conflict gate 足够保守； 但主方法 gagb_qb_conflict_gate 只在 2/4 settings 超过 gb 和 v1 gagb， noise_correction_rate 仍为 0，因此不能作为主方法成立。

1. 背景与动机

v1 GAGB 的 fair minival 已经显示：简单的 center-based 2-hop graph-aware greedy grouping + noisy-label local smoothing 没有稳定证明 GAGB-specific value。它可以构造图感知局部分组，但没有稳定超过 ordinary GB、embedding-only greedy、topology-only、GAGB-matched kmeans/top-k 和 alpha-matched shuffled。

因此 v2 第一轮不再继续调 lambda_h/lambda_t/tau_add，而是检验一个更具体的失败原因： v1 的 q_B 是否过度依赖 noisy local majority，导致 soft target 只是把局部噪声多数类重新灌回训练节点。

2. v2 实验计划

模块 计划内容
固定项 不改 GRACE，不改 frozen embedding，不改 GAGB 构球，不接入 view generation。
核心变化 只改 ball-wise soft target，把 GAGB 从局部分组器改成 noise-aware soft label generator。
Teacher 在 frozen embedding 上训练一个 lightweight linear teacher，只用 noisy train labels，不用 clean labels、val labels 或 test labels。
新增方法 gagb_qb_pred_mix、gagb_qb_teacher_prior、gagb_qb_conflict_gate。
新增控制 topk_gagb_train_matched、topk_gagb_allnode_matched、target-level shuffled sanity。
主判断方法 gagb_qb_conflict_gate。

3. 当前算法流程

Input:
  frozen GRACE embedding H
  graph-aware GAGB grouping B
  noisy train labels y_noisy
  train / val / test masks

Step 1: train noisy-label-only teacher
  teacher = LinearClassifier(H -> class)
  train only on train nodes with y_noisy
  output all-node teacher_probs

Step 2: for each GAGB ball B
  q_label_B = noisy label distribution among train nodes in B
  q_pred_B  = mean teacher_probs among all nodes in B

Step 3: construct q_B
  pred_mix:
    q_B = (1 - beta) * q_label_B + beta * q_pred_B

  teacher_prior:
    q_B = (count_label_B + gamma * q_pred_B) / (n_train_B + gamma)

  conflict_gate:
    q_mix = (1 - beta) * q_label_B + beta * q_pred_B
    only smooth node i if:
      q_mix[noisy_y_i] <= 0.35
      max(q_mix) >= 0.55

Step 4: train frozen linear classifier
  target_i = (1 - alpha_i) * one_hot(noisy_y_i) + alpha_i * q_B
  if conflict gate rejects i:
    target_i = one_hot(noisy_y_i)

4. 三个 v2 方法

方法 公式 / 规则 设计目的
gagb_qb_pred_mix q_B = (1-beta) q_label_B + beta q_pred_B，默认 beta=0.5 直接缓解 noisy local majority，让 teacher prediction 参与球内 soft label。
gagb_qb_teacher_prior q_B = (count_label_B + gamma q_pred_B) / (n_train_B + gamma)，默认 gamma=2.0 把 teacher prediction 当 pseudo-count prior，比 pred mix 更保守。
gagb_qb_conflict_gate 仅当 q_mix[noisy_y_i] <= 0.35 且 max(q_mix) >= 0.55 时才 smoothing 主方法。只在局部 soft distribution 明显反对 noisy label 时尝试纠错，避免 clean damage。

9. 当前支持与不支持的结论

支持

  • v2 target pipeline 可运行，并且 teacher 没有 clean-label leakage。
  • teacher-aware target 构造可以接入现有 frozen-GRACE noisy-label gate。
  • gagb_qb_conflict_gate 足够保守，clean damage 没有增加。
  • CiteSeer 0.2 上有明确 paired positive signal，值得作为现象保留。

不支持

  • Target-only GAGB v2 不能作为主方法。
  • 简单把 teacher prediction 混进 q_B 不能解决 noisy-label self-confirmation。
  • 当前 conflict gate 没有产生真正的 correction signal。
  • 不能写成 GAGB v2 已经稳定优于 ordinary GB 或 v1 GAGB。

10. 希望 GPT 重点审查的问题

  1. NCR 为 0 的根因是什么？ 是 gate 太保守、teacher 质量不足、q_B 分布仍不够尖锐，还是 NCR 这个诊断定义太严格？
  2. conflict gate 条件是否设计错了？ 当前条件只看 q_mix[noisy_y_i] 和 max(q_mix)，没有要求 target top class 与 noisy label 不同后的 margin。
  3. teacher 是否只是复现 noisy labels？ Teacher 只用 noisy train labels 训练，可能没有提供独立纠错信息，只是平滑版 noisy classifier。
  4. 是否应该先诊断被 gate 选中的节点？ 需要检查 gated nodes 中 noisy node 比例、clean/noisy 分布、target top class、teacher confidence 和 ball purity。
  5. 下一步应该转向 ball-quality v2 还是修 target gate？ 当前报告建议转向 prediction-consistency-aware ball construction 和显式 Q(B)。
  6. CiteSeer 0.2 的正信号能否解释？ 它是 teacher-aware target 的真实收益，还是因为 coverage 变低产生了类似正则/少干预效果？

11. 推荐下一步

不建议继续把 target-only v2 当主线打磨。最小下一步应该是一个诊断实验，而不是直接设计 v3： 

For gated train nodes:
  report clean/noisy ratio
  report target argmax vs noisy label vs clean label
  report q_mix margin
  report teacher confidence
  report ball clean purity and noisy entropy

If gated nodes are mostly clean:
  gate is selecting the wrong nodes

If gated nodes include noisy nodes but target argmax still noisy:
  q_B is not correction-capable

If target argmax correct but NCR still 0:
  current NCR diagnostic or alpha strength needs inspection

如果诊断确认当前球无法提供纠错 target，则下一轮应进入 ball-quality v2： 引入 prediction consistency、ball-level quality Q(B)，并只允许高质量球参与 correction target。
