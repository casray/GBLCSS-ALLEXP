# Information Sciences 多代理论文工作流设计

## 1. 目标

以 `paper_final_zh_v29_human_style_20260727.md` 为唯一中文主稿，基于本项目已有实验、日志、结果表、文献图谱与审计报告，形成一篇面向 Elsevier *Information Sciences* 的高质量计算机科学论文。最终稿必须满足四项硬约束：

1. 论文的每个主要 claim 都能追溯到实验结果、公式、图表或可靠文献。
2. 多代理用于制造独立判断和审稿压力，不用于拼接多篇完整论文。
3. 只有一个主笔可以修改 canonical manuscript，以保持术语、论证和文风一致。
4. 不新增未经验证的数字、机制解释、文献或实验结论；负结果和适用边界必须保留。

## 2. 当前材料与流水线入口

现阶段不运行新实验。若审稿代理认为某项核心 claim 缺乏证据，只能将其登记为“需要新实验”或削弱/删除 claim；不得自行生成结果。

## 3. 目标期刊适配

### 3.1 已核实的期刊定位

*Information Sciences* 接收信息、知识工程与智能系统方向的原创研究，强调理论与实践的平衡。本文的图学习、标签噪声、软监督、蒸馏与无图推理主题在期刊公开 scope 内，但稿件必须把贡献表述为可推广的智能信息处理方法，而不是一个只对单个基线有效的工程补丁。

### 3.2 稿件叙事要求

主线固定为：

> 在训练标签受污染、部署阶段不可访问图结构的节点分类中，如何从冻结表征空间提取可靠的局部语义共识，并将其转化为对节点监督和无图学生模型都有效的软监督信号。

贡献表达按下列顺序组织：

1. 问题：带噪标签与无图部署共同造成监督不可靠和结构知识缺失。
2. 洞见：冻结表征中的局部粒球共识可以作为有置信度的软关系教师。
3. 方法：标签无关粒球构造、粒球级半硬目标、节点自适应目标和共识教师蒸馏。
4. 证据：主结果、成对 seed 比较、消融、机制分析和部署开销。
5. 边界：结果仅覆盖实际运行的协议、数据集、噪声设置和表征骨干。

### 3.3 投稿格式门禁

在最终提交前重新核对期刊实时 Guide for Authors。当前先执行以下稳定规则：

- 使用可编辑源文件；最终优先准备 Elsevier LaTeX 源文件。
- 摘要必须独立、简洁，包含目的、方法、主要结果和结论，不在摘要中堆叠消融清单。
- Highlights 单独成文件，每条只表达一个可核实贡献。
- 章节使用清晰的编号结构；表格保持可编辑，图表均在正文中引用。
- 参考文献正文与列表双向一致，DOI 和元数据逐条核验。
- 提交前准备利益冲突、资金、数据/代码可用性及生成式 AI 使用声明；声明内容由作者最终确认。
- 任何尚未从当前官方指南正文直接核实的字数、关键词数量、匿名审稿或图表数量限制，均标记为“提交前再核实”，不得用旧版或其他期刊规则替代。

## 4. 工作流架构

### 4.1 单一事实底座

先建立 `paper_pipeline/00_evidence/claim_evidence_ledger.md`。每一行至少包含：

- Claim ID
- claim 的最窄可支持表述
- 所属章节
- 证据文件与定位
- 数据集、噪声类型/比例、split、seed 和比较协议
- 支持状态：`SUPPORTED`、`PARTIAL`、`UNVERIFIED`、`CONTRADICTED`
- 可允许的机制解释
- 禁止扩张的表述
- 修订决策

事实底座完成后冻结。所有代理只读使用该底座；任何新事实必须先回到 ledger 核验，不能直接写入主稿。

### 4.2 独立审稿代理

并行设置三个互不交流、只读审稿代理：

1. **Narrative & Novelty Reviewer**
   - 检查研究问题、gap、核心洞见、贡献独立性和 *Information Sciences* 适配。
   - 重点寻找“方法像局部技巧”“贡献列表超过证据”“引言承诺大于实验”的风险。

2. **Method & Reproducibility Reviewer**
   - 检查问题定义、符号、算法流程、训练/推理资源边界、复杂度与复现信息。
   - 重点寻找标签泄漏、图信息使用边界不清、方法公式与实现协议不一致的风险。

3. **Experiments & Statistics Reviewer**
   - 检查 baseline 公平性、split、seed、均值/标准差、paired delta、消融和负结果。
   - 重点寻找不具有统计支撑的“显著”“稳定”“普遍”表述。

每个代理只生成审稿报告，不修改主稿。报告必须采用统一 issue schema：

- Issue ID
- Severity：`P0`（事实/完整性阻断）、`P1`（高拒稿风险）、`P2`（可读性或次要完整性）
- Manuscript location
- Problem
- Evidence
- Rejection impact
- Minimal fix
- New experiment required：`YES/NO`
- Claim decision：`KEEP/WEAKEN/DELETE/TEST`

### 4.3 综合编辑

综合编辑只合并问题和决策，不拼接代理生成的句子。输出 `revision_roadmap.md`，其职责是：

- 合并重复 issue，但保留最严重等级和全部证据。
- 对冲突意见给出裁决及理由。
- 区分文本可修复问题与必须新增实验的问题。
- 固定修订顺序：P0 → P1 → P2。
- 为每个 issue 指定唯一验证方式。

### 4.4 单一主笔

主笔是 canonical manuscript 的唯一编辑者。主笔按章节顺序修订，不并发编辑同一文件：

1. 先修复 claim、结构与证据映射。
2. 再修复段落任务、术语和过渡。
3. 最后执行 Elsevier/去 AI 文风审校。

主笔不得因为句子“更漂亮”而改变数字、实验条件或 claim 强度。每次修改必须能映射到 issue ID 或明确的格式要求。

### 4.5 独立终审

修订稿完成后，由未参与写作的终审代理从头检查：

- claim–evidence 一致性
- 引用存在性与引用语境
- 数字、表格、图和正文一致性
- 训练/验证/测试协议
- 生成式 AI 常见科研失败模式
- *Information Sciences* scope 与投稿格式

终审 P0 必须为零；P1 若不能修复，必须作为明确限制保留并由作者决定是否投稿。

## 6. 版本与防污染策略

- v29 永久保留为基线，不直接覆盖。
- 第一轮结构/证据修订输出 v30。
- 中文科学内容冻结后，输出英文 v1；不逐句直译。
- 摘要和引言可以生成多个完整候选版本，但只能整段或整套选择，禁止逐句拼接形成“缝合文”。
- 每轮最多一次综合修订和一次复审；若评分提升小于 3 分且无 P0，停止继续打磨。
- 所有审稿报告保留，不因综合意见而删除反对意见。

## 7. 去 AI 痕迹策略

“没有 AI 味道”不通过同义词替换实现，而通过以下机制实现：

1. 以实验支持的正面科学判断开段，不用防御性否认开段。
2. 每段只完成一个论证任务，首句明确该任务。
3. 将适用范围写入 claim 本身，避免段末连续追加 caveat。
4. 限制集中放在实验设置和结论，不在全文重复道歉。
5. 保留反常结果、失败消融和不占优的场景，并解释它们限定了什么。
6. 删除实验目录、运行编号、内部讨论和修订历史等项目内词汇。
7. 由单一主笔统一术语、句长和论证节奏，再进行人工逐句朗读与最终决定。

## 8. 验收标准

### 8.1 科学完整性

- 所有摘要和引言中的主要 claim 均出现在 ledger，且状态为 `SUPPORTED` 或明确降级后的 `PARTIAL`。
- 所有核心数值能追溯到原始 CSV/JSON/日志。
- baseline、split、noise、seed 和评估协议可复现且可比。
- 不存在伪造或无法定位的引用。

### 8.2 审稿质量

- 三份独立审稿报告均完整使用统一 schema。
- 所有 P0/P1 都进入 revision roadmap，没有静默丢弃。
- 修订后的每个问题都有 `RESOLVED`、`PARTIAL` 或 `ACKNOWLEDGED` 状态。

### 8.3 写作质量

- 题目、摘要、引言、方法、实验和结论使用同一中心问题和术语。
- 每段可被反向概括为一个清晰命题。
- 不出现超出协议的“普遍”“显著”“最先进”等表述。
- 论文读起来像一位研究者持续推进同一论证，而不是多个代理的文本拼接。

### 8.4 期刊适配

- 编辑能在题目、摘要和引言前两页内识别原创性、信息科学意义及理论—实践联系。
- 投稿源文件、Highlights、图表、声明和参考文献满足提交时的实时 Guide for Authors。

## 9. 风险与处理

- **风险：工作树已有大量用户改动。** 只新增本工作流目录和新稿版本；不重置、不清理、不覆盖现有文件。
- **风险：代理事实漂移。** 代理只读使用冻结 ledger；新增事实必须退回 Evidence Auditor。
- **风险：审稿意见互相迎合。** 并行审稿在互不可见条件下完成，再统一综合。
- **风险：主稿被多次往返破坏。** 限制修订轮次，每次修订前后保存版本和问题追踪表。
- **风险：官方作者指南页面暂时无法直接读取。** 当前只采用已核实的 scope 和稳定 Elsevier 规则；所有期刊特有限制在提交前从官方实时页面再次核对。
- **风险：Windows 内置浏览器崩溃。** 禁止使用 ChatGPT/Codex IAB；公开资料只用 Web Search，登录型网页仅在用户明确许可且 `@Chrome` 可用时操作。

## 10. 非目标

- 不安装大量功能重叠的写作 skill。
- 不让多个代理各写一篇完整论文后拼接。
- 不在未核实证据前补实验结果或扩大 claim。
- 不在本阶段运行新实验或改变训练、验证、测试协议。
- 不把降低 AI 检测分数当作科学质量目标。
