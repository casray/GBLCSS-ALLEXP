# 这一轮要回答什么

上一轮 NP 相对旧版提高，但同时改变了球数、球内训练支持量和具体投票者。
这轮拆开这些因素，避免把整体收益直接解释成某个机制已经成立。

## 对照怎样读

| 名称 | 操作 | 主要比较 |
|---|---|---|
| CE | 原始观测标签训练 | 检查干净损害和基本收益 |
| OLD64 | 历史默认球与原 LCSS | 衡量相对已投稿规格的修复 |
| NP | 票数差异与邻居成员差异共同优化 | 完整候选 |
| SUPPORT | 同树同动态规划，只优化票数差异 | NP−SUPPORT 检查成员保留的额外贡献 |
| COUNT | 同树同 NP 实际球数，按 SSE 增益逐次分裂 | NP−COUNT 检查仅改变总球数是否足够 |
| KMNP | k-means 使用 NP 的实际球数 | 检查普通聚类能否达到同样效果 |
| KMOLD | 同一实现的 k-means 使用旧版实际球数 | KMNP−KMOLD 检查粒度变化 |
| KNNMATCH | 每个查询与 NP 使用完全相同票数的近邻 | 检查具体证据选择的质量 |

R0 是投稿规格的原始属性 MLP。R2 是先向冻结 GRACE 表示对齐，再冻结编码器、
训练分类头的属性学生。两者最终都输入原始 X，但训练资源与阶段不同，不混合宏平均。

## 为什么不能只看平均票数

相同球数可以对应不同的球内训练节点分布；较大球包含更多查询节点，因而在逐节点
平均中权重更高。同样，平均票数相近也不保证具体投票者相同。三项几何代价分别保留
在 geometry.csv，分类收益则必须由实际训练结果判断。

## 如何判读结果

- NP 与 SUPPORT 接近，只能说当前比较未检测到足够大的成员保留增量，不能声称
  两者在所有条件下等价，更不能倒推旧版提升中多少比例来自支持量。
- 若 NP 优于 COUNT，但不优于 SUPPORT，说明仅匹配总球数不足，局部支持配置可能
  比总数更重要；仍不能据此声称 32 是最优支持量。
- 若 KMNP 仍更好，保留原生成器修复的实用结果，不能将它写成粒球独立优势。
- 同时报告 clean、带噪、macro-F1 和目标 Brier。目标质量与测试分类不是同一指标。
- seed0 已用于前一轮观察；seed1/2 是冻结规格后的配对复验。历史 GRACE 仍共享，
  三种子并不等于三次独立自监督预训练，且数据集也不是全新确认数据。

准确率差异使用百分点；标准差使用种子间样本标准差。先对每个种子计算相同九个带噪
条件的均值，再计算三个种子的均值和标准差，不把九个条件当九次独立重复。

## 运行范围

三图、三种子、四条件、两骨干、八臂，共 576 个结果单元。复用的历史结果明确标注
来源；新增模型实际数量与别名单元数量分开报告。判定门槛见训练前冻结的 PLAN.md。
本轮不授权自动叠加 small-loss、加权损失、软归属或根据测试结果扫描支持量。
