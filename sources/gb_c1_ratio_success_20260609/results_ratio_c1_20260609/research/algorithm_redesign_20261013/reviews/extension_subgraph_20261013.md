# 子图／局部—全局图自监督对粒球节点分类方案的启发

**调研日期：2026-10-13。** 本文只讨论单个大图上的节点表示学习与节点分类；“局部—全局”特指某个目标节点的局部上下文与同一目标节点在原图中的表示，不把图分类中“每张图一个向量”的做法混称为节点表示。

## 结论先行

建议首轮把 **PiNGDA 与 LS-GCL 作为两个单独的节点自监督基座正面对比**：PiNGDA代表近期可学习拓扑／属性增强，LS-GCL代表显式rooted-subgraph/local-global结构。它们先各自与GRACE比较，不把PiNGDA、LS-GCL、VICReg和粒球一次堆叠。若局部上下文确有增益，再测试“保留节点自身表示 + context-only 分支”；粒球只用于之后的软构球，不替换节点表示，也不把同球／异球直接变成硬正负样本。

理由是：SUBG-CON、LS-GCL 已经证明“以目标节点为根、从子图提取上下文”是节点任务的既有表示方式；HPoolGCL 已经把池化保留／丢弃节点转成跨粒度节点对比；EA-MGCL、IGCL-CS、HAUL 已经覆盖社区节点／社区层级信号；LAD 已经覆盖局部样本的假负样本加权。更关键的是 GBGCL 与 SAGHL 是直接的粒球近邻，SAGHL 的官方摘要还明确声称标签噪声鲁棒性。因此，“首次将粒球、社区、层次对比或软负样本权重用于图学习”都不能作为安全的新颖性 claim。可能值得验证的窄差异是：**用粒球的可信度与软成员关系，构造目标节点锚定、保留根节点身份的局部上下文；将其作为 GRACE 节点表示的补充，并在固定噪声标签协议下验证。** 这只是待检验假设，不是现有证据支持的结论。

## 先统一“表示空间”：节点、局部子图和整图不是一回事

对单大图节点分类，模型最后必须为每个节点 (i) 产生与该节点身份对齐的表示 (h_i)。下面三类表示互有关联，但不能互换：

1. **根节点／目标节点表示**：在某个局部子图或全图中编码后，取目标节点自身的隐藏向量 (h_i)。它保留“现在要预测的是谁”。
2. **目标节点的局部上下文表示**：在以 (i) 为根抽出的 ego/PPR 子图中，对节点表示做池化得到 (c_i)，或从局部子图中再次取根节点表示。它描述“节点 (i) 周围是什么”，本身不应取代 (h_i)。
3. **整图读出表示**：把整个输入图池化为一个向量 (g)。它可用于整图分类，也可作为单大图节点任务中的共享上下文，但单独的 (g) 不区分目标节点，不能直接视作每个节点的 (h_i)。

据此，表示空间的反设计应从 GRACE 的节点级 (H) 出发：保留跨视图同一节点的对齐和节点身份；额外构造每个节点的 rooted context；粒球只改变局部上下文如何汇总及其可信度。一个可测试的输出形式是 (z_i=f(h_i^{\mathrm{self/root}}, c_i^{\mathrm{local-ball}}))，使用残差、拼接后投影或门控融合三者之一，并固定其他部分。若采用 LS-GCL 的全图分支，使用的是原图编码后**同一目标节点**的 (h_i^{\mathrm{global-node}})，不是全图读出 (g)。

### SUBG-CON、GCC、MVGRL 的关键区别

| 方法 | 对比对象与输出 | 是否是单大图节点级局部表示 | 对粒球设计的启示／边界 |
|---|---|---|---|
| SUBG-CON (ICDM 2020) | 每个节点按 PPR 排名抽取 top-(k) rooted context；GNN 得到根节点表示和池化子图摘要；根节点表示与自己的局部摘要为正例，打乱／替换的其他上下文为负例。论文指出子图会重叠，因此用带 margin 的目标，避免硬 BCE 强迫所有上下文绝对分离。 | **是，直接做目标节点的局部子图表示学习。** 下游在节点表示上做分类。 | 最直接的 rooted-subgraph 机制参照；重叠上下文不适合当作彼此绝对互斥的硬负例。它没有粒球或标签噪声协议。 |
| GCC (KDD 2020) | 将不同网络中的 (r)-ego network 当作结构实例；RWR 重启概率 0.8 生成两个视图，匿名化节点身份，用 InfoNCE 做实例级结构预训练，再迁移到若干节点／图任务。 | **不是针对目标单图的属性节点表示基座。** 虽有节点分类迁移评估，但预训练重点是跨网络 ego 实例和结构迁移；不应因其中含节点任务就称其为“同一大图中每节点 rooted context + 特征”的方法。 | 可参考结构预训练、ego augmentation 和匿名化；其设置没有直接覆盖用户的属性信息与噪声训练标签。跨 ego 实例的负样本仍可能语义重叠。 |

| LS-GCL (Neural Networks 172, 2024) | 每个目标节点用 PPR 构造语义子图；共享 GNN 同时产生该目标节点的子图级表示和池化子图表示；全图视图再产生同一目标节点的表示；三层级对比。 | **是，最贴近本问题的节点分类基座。** 同时区分根节点、局部子图摘要和全图中的同一节点。 | 适合作为 rooted-context 结构基座与机制对照。它已覆盖“局部子图 + 全图 + 节点”多视角，所以新意必须来自粒球可信软聚合如何改进 rooted context，而非泛称 multi-level/local-global。出版社正式记录摘要报六数据集；arXiv版本报五数据集，版本差异需逐版核表。 |

## 粒球新颖性边界：GBGCL 和 SAGHL 不能略过

- **GBGCL** (TPAMI 2026, DOI 10.1109/TPAMI.2026.3720194)：本段先前依据题名把它判断为多类型异构图，现根据用户补充全文撤回。实际研究异配图；同球正对、跨球负对，式7–8依赖类别标签分球，Table III标XAY。全文未给独立标签噪声注入实验，代码与标签使用范围未核实。详见更新后的 [全文卡](core/GBGCL.md)。它已足以否定“首个粒球图对比”主张。
- **SAGHL** (Engineering Applications of AI 181 Part 2, 2026-10-01, 115428) 是更直接的近邻：以 hub 引导的层次粒球分解生成超边，融合多尺度超图表征，并以超边引导正／负采样和尺度／密度动态温度联合分类与对比；官方摘要明确声称缓解标签噪声。[出版社页面](https://doi.org/10.1016/j.engappai.2026.115428)。目前本地 SAGHL 卡片以及出版社摘要／可见片段已核，但标签噪声的具体注入方式、是否在粒球生成中使用标签、数据划分、seed、均值方差、与 GBGCL 等方法的对照尚未完成全文核验。因其声称和当前研究目标高度重合，**任何论文投稿前必须取得并逐段核读全文和补充材料**；在此之前不得宣称粒球对比首次用于标签噪声鲁棒节点分类。
- 项目本地的 **MGBCC** 卡片也已有多视角聚类中的粒球交叠／成员关系关联；它不等同于节点级图对比或噪声标签鲁棒方法，但提醒“粒球 + 软／硬跨粒关系”本身也要回查既有方向。[本地阅读卡](core/MGBCC.md)。

上述近邻表明：设计若只是“用粒球做社区”“加入粒球级损失”“把不确定负样本降权”，分别会撞上 EA-MGCL／IGCL-CS／HAUL／HPoolGCL、SAGHL／GBGCL、LAD 等先例。候选贡献必须同时说明**锚点是目标节点、粒球提供何种可校准局部证据、该证据如何补充根节点自身特征**，并用匹配容量的非粒球上下文池化对照证明收益来自粒球信号本身。

## 建议的具体基座和实验顺序

### PiNGDA + 局部 R/VICReg 候选的推荐与严格审查

**建议首轮把 PiNGDA 与 LS-GCL 作为两个单独的节点自监督基座正面对比。** PiNGDA 是近期节点级 CL 基线，学习拓扑和属性扰动；LS-GCL 是直接的 rooted-subgraph/local-global 节点方法。两者各自单独与 GRACE 比，才能看出变化来自可学习增强还是局部语义子图。首轮不要组合 PiNGDA、LS-GCL、VICReg 和粒球。若实验证明局部上下文有增益，再从当前表现较好的基座加 context-only 分支；LS-GCL 同时是结构参照，PiNGDA 可作现代增强基座。原论文 benchmark 与项目的 noisy-label 协议不同，不能比较论文表格数字。

PiNGDA 原文不是局部子图方法：它对原图与可学习 pi-noise 图编码，以节点 i 的两视图嵌入为正例，其他节点嵌入进入 InfoNCE 负项；可学习噪声作用于边和属性。节点分类协议为无监督预训练后训练 L2 正则 logistic probe，七个节点数据集采用随机 10/10/80 划分，并报告多次划分／seed 结果。这里的 beneficial “noise” 指自监督图增强扰动，不是训练标签噪声。其原始节点 InfoNCE 仍将其他节点作为负例，所以不能说 PiNGDA 消除了假负样本；候选 VICReg 只是避免新加局部 ego 负例，不移除原有节点级假负例。[ICML/PMLR 原文](https://proceedings.mlr.press/v267/huang25ao.html)，[作者 arXiv 全文](https://arxiv.org/html/2505.19024)。

对候选 R_i = MLP([h_i, mean_{j in S_i excluding i} h_j]) 并让两个视图同根 R 做 VICReg，主要反对意见有四条：

1. **中心捷径会掩盖上下文是否学到。** h_i 在两增强视图中具有同一节点身份，通常比邻域均值更稳定；MLP + VICReg 可能只靠 h_i 完成视图一致。VICReg 的方差／协方差项抑制整体坍塌，但不会强迫模型使用邻域上下文。若 R 再用于构球，球可能主要复刻 h_i 的聚类，而不是局部上下文。
2. **排除根索引不等于消除根信息。** 若 h_j 是 PiNGDA 对整图编码的节点表示，message passing 已可能将根 i 的信号传播进邻居 h_j；把 i 从均值索引中删掉，并未从 h_j 的感受野中删掉。此时均值是邻居全图表示的再次汇总，不是独立编码的 rooted subgraph。它也可能近似一次额外传播，不能把其效果自动归因于“子图语义”。
3. **共享 H 上的损失可能冲突。** PiNGDA 的节点 InfoNCE 继续以其他节点为负例；VICReg 与 PiNGDA 同时更新共享 encoder，可能互补，也可能梯度冲突或由其中一个目标主导。需做 loss 消融和训练稳定性检查，不能预先断言互补。
4. **组件拼接本身不是新颖性。** PiNGDA 可学习增强、局部均值、VICReg、粒球下游构造分别都有成熟先例；组合是可执行的候选，不自动构成方法贡献。需要让粒球对等规模 kNN／社区／普通 pooling 的对照证明增益来自粒球信号。

**接受上述批判后的最简版**是把自身表示与上下文严格分开：每个视图 v 先算 C_i^v = phi(mean_{j in S_i^v excluding i} H_j^v)，只对同根 C_i^1, C_i^2 加 VICReg；PiNGDA 的 H_i 继续由原始节点 CL 目标训练，并始终保留在分类／构球表示中。构球空间用固定拼接：

R_i = [sqrt(1-beta) * normalize(H_i), sqrt(beta) * normalize(C_i)], beta in {0, 0.5}.

这样 beta=0 是 H-only 球对照，beta=0.5 检查上下文是否使球表示更有用；固定权重避免可学习融合把负结果藏起来。要准确命名：若 H_j^v 来自整图 encoder，这仍是“全图节点表示的邻域均值”，不是独立 rooted-subgraph encoding。只有在每个 S_i 的诱导子图上编码／聚合并与 LS-GCL／SUBG-CON 比较后，才适合称为局部子图编码。

至少增加四类控制：**extra propagation**（检验均值分支是否只是再传播一层）、同参数预算的普通局部 pooling、固定子图大小的邻域打乱（检验真实 rooted context 是否重要）、LS-GCL rooted-context 对照。粒球再与 kNN、社区、随机等规模分组比较。若主要问题只是“换球空间”，第一阶段还可先在冻结 GRACE/PiNGDA H 上比较 H-only 与 H+context 构球，不训练 VICReg；先证伪“新空间改善粒球聚类／纠错”，再决定是否投入新的 SSL 目标。粒球第一轮不参与 PiNGDA/VICReg 反传，避免 GB 用自身输出自强化。

因此准确表述是：VICReg 分支**不新增局部上下文负例**，不等于消除了 PiNGDA 原有节点 InfoNCE 假负例。第一轮也不加同球硬正／异球硬负，不让 noisy Y 参与构球、局部权重或 SSL 正负对。
### 优先级

1. **P0：把比较协议钉死。** 复核项目既定 train/validation/test split、20/10/70 配置、训练标签噪声 mask、seed 和 GRACE 的 H/Z 评估路径。所有基线和消融用相同 mask、split、head、early stopping 与 seed；原论文公开 benchmark 分数不能代替本协议内重跑。
2. **P1：PiNGDA 与 LS-GCL 单独正面对比。** 在项目既定协议下分别适配 GRACE、PiNGDA、LS-GCL，先不组合。PiNGDA测可学习拓扑／属性增强，LS-GCL测 rooted PPR local-global 结构；SUBG-CON是精简局部基线。结果决定后续只选一个扩展骨架。
3. **P2：先诊断 context，再训练 VICReg。** 在冻结的 H 上比较 H-only 与 H+普通邻域均值构球，固定拼接 beta=0/0.5；配合 extra propagation、普通 pooling 和邻域打乱。只有 context 对同一 LCSS 流程有独立增益，再做 context-only 同根 VICReg；分类始终保留 H_i。
4. **P3：做粒球局部池化的单因素比较。** 在相同目标节点、同一局部节点集合、同一编码器和参数预算下，比较普通 mean/attention pooling、kNN 或特征聚类分组、随机等规模分组、社区聚合、粒球软成员＋可信度。输出至少比较 H-only、context-only、固定融合；再把 LS-GCL 全图目标节点分支作为受控消融。
5. **P4：再做假负样本和噪声标签诊断。** 记录不同根节点 ego/PPR 子图的重叠程度，评估若用跨节点负例时 overlap 是否系统性制造假负例；先用 margin／软权重等温和对照，不把任何局部样本永久认作同类。分别报告 clean validation/test 指标与 noisy train-label 下的指标，并注明 SSL 阶段是否完全 label-free。
6. **P5：通过门槛后再扩展。** 只有粒球信号超过等规模 pooling/community 对照、跨数据集和噪声率结果稳定，且提升不小于 seed 波动时，才考虑额外的粒球层级对比或更复杂的全局分支。若相同预算的普通池化／社区基线达到相同效果，或结果只在单一数据集／单一噪声 mask 有效，应停止“粒球语义聚合优于通用局部池化”的主张。
### 结论应该怎样写

若 SSL 不使用标签，而噪声只出现在下游分类器的训练标签中，实验最多支持“该表征对噪声监督下的下游拟合更有用／更稳定”；它**不自动支持**“粒球纠正了噪声标签”或“SSL 对标签噪声鲁棒”。只有将噪声 mask、清洁对照和各噪声率固定，多个 seed 以 mean±std 报告，且提升超过波动并跨多个数据集成立，才有理由把它写为稳定改善。若训练目标直接依赖 noisy labels，则必须单独拆解粒球机制是否放大了错误标签传播。
