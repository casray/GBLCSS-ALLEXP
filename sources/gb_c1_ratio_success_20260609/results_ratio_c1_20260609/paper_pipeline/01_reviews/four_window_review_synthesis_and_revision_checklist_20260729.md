## 1. 总体判断

四份审稿意见高度一致。论文当前的主要风险不是精度不足，而是以下四类问题：

1. 实验协议的表述与 NoisyGL 原始协议不一致。
2. 粒球的独特性和必要性不能按“优于其他邻域构造”来声称。
3. 旧版多数票平局和置信权重存在统计定义问题。
4. 论文同时混用了开发期结果、冻结后结果、历史结果和当前结果，容易造成选择性报告的印象。

其中，平局偏置和最近工作缺失已经被新实验解决。现在不应再次围绕这些问题设计新机制，而应把新结果正确合并进论文。

删减稿不适合作为投稿稿。它删除了 kNN/k-means、LOO、H-access 和开销分析，恰好触发了冷启动审稿人最合理的质疑。删减稿只能作为压力测试材料。

推荐的投稿底稿不是原始 v29，也不是当前偏审计报告风格的 v31，而应创建 v32：

> 保留 v29 的完整证据披露和相对自然的写作风格，替换为 v31 的 tie-safe 定义、正式最近工作结果和收紧后的 claim。

## 3. P0：投稿前必须完成

### P0-1 确立唯一数据与稿件谱系

- 创建 v32，以 v29 的章节与披露完整度为写作底稿。
- 主实验数字全部替换为 tie-safe v2 的不可变结果。
- 最近工作结果全部来自正式 625 行网格。
- 历史旧规则结果只允许出现在明确标注的历史诊断或附录中。
- 不再并行维护互相冲突的“主版本”。

验收标准：

- 每个主表单元格均能追溯到 raw CSV、seed、protocol hash 和汇总脚本。
- 正文不存在旧平局规则和 tie-safe 规则混算。

### P0-2 修正 NoisyGL 协议表述

不得再写“沿用 NoisyGL 评测协议”。建议改为：

> 噪声类型及其生成形式参考 NoisyGL，而本文采用固定的 20%/10%/70% 划分，仅污染训练标签，并使用干净验证集进行模型选择。

全文统一披露：

- transductive 节点分类；
- train-only synthetic label noise；
- 20%/10%/70% split；
- clean validation；
- test labels 始终不参与训练和选择；
- 方法目标构造不读取 clean labels，但实验流程使用 clean validation。

### P0-3 补一个协议敏感性表

目的不是重跑全部主表，而是回答“结论是否依赖 clean validation 和 train-only corruption”。

建议最小矩阵：

- 数据集：Cora、CiteSeer、CoraFull；
- 噪声：uniform 0.4；
- 方法：GB-LCSS、GSDN、PosteL、JoCoR、MLP+CE；
- seeds：0-4；
- 协议：当前 clean-val/train-only 与 NoisyGL-like noisy-val/train+val 两种。

固定所有超参数，不根据第二种协议重新搜索。

成功标准：

- GB-LCSS 相对 MLP+CE 和随机分组的方向在 3/3 数据集保持；
- 与 GSDN/PosteL 的相对强弱可变化，但必须完整披露；
- 若性能显著依赖 clean validation，则将 clean-validation conditional 提升到摘要与局限。

### P0-4 重写主 claim 和摘要结果句

禁止：

- “总体 SOTA”；
- “粒球优于 kNN/k-means”；
- “24/25 无条件获胜”；
- “NoisyGL 标准协议下”；
- “无需任何干净标签”。

可以写：

- 真实粒球分组相对随机分组在 25/25 设置上获得正增量；
- tie-safe GB-LCSS 在相同资源条件下优于 PosteL-noIPL、ALS 和 SALS；
- 与 GSDN 呈数据集和噪声体制相关的互有胜负；
- 粒球是固定构造预算的局部共识实现，其价值不依赖逐节点邻域尺度选择；
- 实验范围是合成训练标签噪声、transductive、clean-validation 条件。

### P0-5 恢复完整的公平性证据

### P0-6 整理主表层级

## 4. P1：显著提高接收概率

### P1-1 `alpha` 诊断，而不是立即改算法

报告：

- 每球训练票数；
- tie rate；
- `alpha` 分桶后的真实 target correctness；
- `alpha` 与投票 margin、entropy、球大小的关系；
- 不同类别先验下的分布。

若 `alpha` 与可靠性基本单调，可将其表述为可解释启发式权重。若不单调，再考虑 class-prior-aware 或 finite-sample-aware 替代式，并对全部主结果重跑。

### P1-2 增加类别不平衡与校准指标

至少在五个核心数据集的 uniform 0.4 下报告：

- macro-F1；
- balanced accuracy；
- ECE 或 Brier score。

软监督方法只报 accuracy 不够完整。若已保存 logits，可直接后处理；否则只补最小矩阵。

### P1-3 加一条简洁理论说明

不追求复杂定理。建议只给：

- 对称噪声下，局部多数类排序被保持的条件；
- 有限票数下多数投票错误概率的浓缩界；
- 明确说明 pair/instance noise 不满足同样保证。

理论作用是解释“为什么中等规模局部聚合可减弱独立噪声”，不能伪装成对全部噪声类型的保证。

### P1-4 选择一个外部有效性补充

三种方向只选一种：

- 一个真实错标案例；
- 一个中等异质性图；
- 一个 inductive/new-node case study。

不要同时扩展真实噪声、异质图、inductive 和 OGB。那会把一篇范围清楚的论文拆成四篇未完成的论文。

### P1-5 端到端方差和开销写实

- 合并已有 3×3 GRACE seed 实验；
- 区分预训练方差、下游方差和总方差；
- 报告 GRACE 预训练、构球、分类器训练、推理的墙钟时间和峰值显存；
- 若声称粒球相对 kNN 有效率优势，必须在相同实现和硬件上给出构建时间、存储和推理成本。

## 5. P2：文字与格式收口

- 所有表从表 1 开始，删除“表 0”。
- 题目中加入 `transductive` 或在摘要第一段明确限定。
- 摘要只保留一组核心量化结果和一条边界，不写实验日志式数字清单。
- 引言贡献压缩到三条。
- 结果段首句先给结论，再给数字和解释。
- 将“证明”“决定性变量”“本质原因”改为与证据强度匹配的“表明”“支持”“与……一致”。
- BatchNorm/Dropout 的训练与推理状态写清。
- pair noise 类别映射、instance noise 随机种子和生成公式放入附录。
- 统一参考文献卷期页码、DOI、方法年份和 adapted 标记。
- Highlights 每条满足期刊字符限制。

## 6. 不建议现在做的工作

- 不全量扩到 10 seeds。
- 不再次调整 `beta`、球数、粒度或 soft target 公式。
- 不为了视觉上获胜删除 kNN、H-access、LOO 或失败数据集。
- 不把蒸馏扩展升级成主算法。
- 不追加大量只做 clean-label 的 GNN-to-MLP 方法。
- 不声称粒球具有不可替代的精度优势。

## 8. 停止标准

以下条件满足后应停止继续改算法，转入投稿：

- 协议表述与实际代码一致；
- tie-safe 主网格和最近工作网格完整；
- clean-validation 依赖已有敏感性证据或醒目限定；
- 粒球可替代性、LOO、H-access 和失败数据集均已披露；
- 主要统计比较有配对 CI 和 Holm 校正；
- 匿名复现包可实际运行；
- 摘要、引言、结论的 claim 与表格逐句一致。

此后继续追求 0.5--1 pp 的局部精度提升，对接收概率的收益低于修正协议、复现和定位问题。
