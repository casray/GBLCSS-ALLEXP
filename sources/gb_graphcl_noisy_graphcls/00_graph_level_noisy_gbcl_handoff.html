旧实验核心结论

旧项目在 Cora 节点分类、frozen GRACE 表示、symmetric 0.4 噪声、ratio split 等设置下， 系统验证了多条粒球后处理路线。最重要的总教训是：

冻结通用节点表示上的粒球结构没有稳定证明出 kNN consensus 之外的独立增量。 粒球有局部结构信号，但在当前 node-level homophily 图任务中，这些信号大多被 kNN 共识覆盖，或者无法转化成下游收益。
阶段 做了什么 关键结果 对新方向的教训
S2a headroom / soft target frozen GRACE 表示上做 GB soft target、reweight、oracle CE 诊断。 oracle 有约 3.4pp headroom，但真实 GB / DCGB soft target 无法有效利用球成员关系。 问题不是完全没油水，而是“球信号到训练目标”的转化形态不对。
S2-redesign-v1 selection 改成 commit-style sample selection。预注册方法为 reliable mutual-kNN ball。 单格主 gate 失败：sel_dcgb_emb 0.7788 < gb_soft 0.7962。但 selection 机制能显著赢 no-ball/shuffled/random。 commit-style 比 soft target 更能转化局部可靠性，但当时的主球构造不够稳。
S3 Phase 1 5 seed 验证 ordinary GB、reliable DCGB、topk、shuffled/random/noball。 sel_dcgb_emb 0.8002 > topk 0.7969 > sel_gb 0.7702。DCGB 对 shuffled/random/noball 5/5 成立。 reliable 局部信号是稳健正信号；seed0 的 ordinary GB 倒挂是假象。
Q2: DCGB vs topk 同 coverage、同 schedule、topk k 匹配球大小，检验“显式建球是否多于 kNN”。 DCGB test 只比 topk 高 0.327pp，t≈0.71 不显著；selection precision 和 noise exclusion 反而 0/5 输给 topk。 在 frozen node embedding 上，显式建球不能作为独立卖点。
Density-guided GB 引入 GBmooer 风格的球级密度结构：density × compactness × noisy consensus。 sel_density 0.7714 < topk 0.7969，但 density 赢自己的 shuffled/random。 球级密度结构不是噪声，但在 frozen GRACE 上仍被 topk 覆盖。
最小 encoder coupling 在 GRACE init 后加弱球损失，检查球质量是否改善。 coupled 与 baseline 的 purity 完全相同；球损失被 GRACE loss 淹没，预注册早停。 轻量 coupling 不够。若要让球成为主角，需要真正 ball-aware 表示学习，而不是小权重补丁。

为什么转向图级任务

旧实验的失败不是“粒球完全没有信息”，而是 node-level frozen GRACE 条件下， 粒球结构很难提供 kNN consensus 之外的可转化增量。图级任务更接近 CGBC 和 GBmooer 的成功条件。

  • 节点任务的 homophily 会让局部一致性饱和。 邻接、表示和 kNN 已经高度重合，粒球容易退化为 kNN 包装。
  • 图级分类是样本级 i.i.d. embedding 空间。 每个图是一个样本，更适合构建局部密度、多尺度球和成员一致性。
  • 对比学习可以先塑造 graph embedding。 GraphCL/InfoGraph/MVGRL 等骨架可以让相似图靠近，再让球在这个空间中做可靠区域建模。
  • 去噪 headroom 更可能足够。 图分类可系统设置 symmetric、pair/asymmetric、高噪声，避免 Cora 单格 headroom 太小的问题。

新实验主方向

主攻方向： 图级噪声标签分类 + 图对比表示学习 + 粒球去噪。

建议英文题目雏形：

Granular-Ball Assisted Contrastive Graph Representation Learning for Noisy-Label Graph Classification

建议中文题目雏形：

面向噪声标签图分类的粒球辅助图对比表示学习

核心流程

  1. 选择图分类数据集，优先 NCI1，PROTEINS 作为辅助，MUTAG 仅用于 debug。
  2. 用 GIN encoder + GraphCL/SimCLR-style augmentations 训练图级 graph embedding。
  3. 在 graph embedding 上构造 granular balls，优先考虑 density-guided 或 multi-scale GB。
  4. 注入训练标签噪声，只污染 train labels，validation/test 保持 clean。
  5. 用 GB 做 sample selection、local label smoothing 或 label correction。
  6. 与 kNN、kmeans、shuffled/random GB、robust CE 等强对照比较。
  7. 只有当 GB 明确赢过 kNN/kmeans 后，才进入 encoder coupling 或更复杂方法。

第一阶段 Gate

第一阶段不是完整论文方法，而是回答一个硬问题：

在图级 i.i.d. embedding 空间里，GB denoising 是否能稳定超过 kNN/kmeans denoising？

推荐设置

数据集 NCI1 主 smoke；PROTEINS 辅助；MUTAG 只做管线 debug；DD/OGBG 后续加。
表示骨架 先用 PyG + GIN encoder + GraphCL/SimCLR-style augmentations 跑通，不必一开始绑定复杂外部 repo。
噪声 先 symmetric 0.4；通过后补 0.2 / 0.6；pair/asymmetric 作为第二阶段。
seed 先 seed0 冒烟，只看管线和 headroom；正式 gate 用 5 seeds。
主指标 test accuracy at best validation、selection precision、noise exclusion recall、paired seed delta、mean/std。

最低对照组

  • GraphCL embedding + CE noisy
  • GraphCL embedding + robust loss，如 SCE 或 GCE
  • kNN selection / smoothing
  • kmeans selection / smoothing
  • GB density / multi-scale selection
  • shuffled GB / random GB
  • clean-label oracle，只作 headroom 诊断，不作为方法

通过标准

  • GB 在 test 上稳定赢 kNN 和 kmeans，建议门槛为 5 seeds 中至少 4 seeds 胜出。
  • mean gain 至少 0.5pp，最好达到 1pp；如果 std 很大，需要 paired delta 支持。
  • selection precision 和 noise exclusion recall 也应支持 GB 更可靠，而不是只有 test 偶然更高。
  • shuffled/random GB 明显掉，证明不是分组数量或 coverage 造成的假象。

失败标准

  • GB 被 kNN/kmeans 稳定追平或超过。
  • GB 只赢 CE，但不赢局部对照。
  • 只在一个小数据集或一个 seed 上有效。
  • clean oracle headroom 很小，说明该设置不适合展示去噪收益。

第二阶段才考虑的内容

以下内容不要在第一阶段就混入，否则失败原因会变复杂。

  • Encoder coupling：只有 frozen graph embedding gate 通过后，再设计 L = L_contrastive + λ_ball L_ball + L_robust_cls。
  • 多尺度 GB：先验证单尺度/密度 GB 是否有信号，再扩展。
  • pair/asymmetric/high-noise：作为稳健性和更大 headroom 的扩展，不与第一张 gate 表混报。
  • 更换骨架：先跑通一个 GIN + GraphCL-style baseline，再考虑 InfoGraph、MVGRL、GCC 或更强 encoder。

严格禁止重复的旧坑

  • 不要把 same-ball membership 直接当 hard positive。
  • 不要做全量 prototype pulling 或 hard inter-ball negative separation。
  • 不要只比较 CE baseline，必须保留 kNN/kmeans/shuffled/random。
  • 不要从单 seed、单数据集、within-std 小提升宣称成功。
  • 不要让 clean labels 进入训练、构球或方法选择。clean labels 只能用于 oracle/diagnostics。
  • 不要把 graph-level 结果和旧 node-level Cora minival 结果混成一张表。

给 Claude 的边界提醒

你可以设计具体算法，但请先把第一阶段写成预注册 gate。 当前最重要的问题不是“方法复杂不复杂”，而是图级空间里 GB 是否有 kNN/kmeans 之外的独立去噪价值。

如果 gate 失败，要如实降级或换任务；不要通过调参、换 coverage、删强对照来保留粒球卖点。
